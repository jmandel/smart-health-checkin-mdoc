# Appendix A. Conformance checklist

This checklist indexes normative obligations defined elsewhere in SMART Health Check-in 1.0. It does not create independent requirements. Rows apply to the stated conformance target when that target, feature, deployment profile, or fixture profile is claimed.

| ID | Target | Level | Section | Checklist item | Evidence/validation |

| A-001 | Deployment/profile author | SHALL | §4.1.7 | State constrained targets, optional features made mandatory, trust layers in scope, and additional validation/security/privacy/fixture expectations. | Conformance claim or profile text names target, feature set, spec version, policy deltas, and assurance assumptions. |
| A-002 | Conformance/fixture author | SHALL | §4.1.7 | Derive tests, schemas, CDDL, fixtures, and byte ladders from normative requirements and explicitly restated appendices. | Test metadata identifies target, feature set, section reference, expected outcome, comparison mode, and fixture trust status. |

## Organizer notes

**Strengths.** This attempt is broad and row-oriented, with separate targets for core clinical exchange, same-device mdoc, optional `readerAuth`, kiosk creator/phone/completion/provider roles, deployment/profile authors, fixture authors, security, privacy, registry, and internationalization. It uses stable section references and avoids treating Appendix A as a source of new behavior.

**Caveats.** The checklist is intentionally dense; an editor may want to split it into subsections matching §4.7 groups. Some rows cluster closely related validations to keep the table usable, especially for §8 and §9 cryptographic processing.

**Open issues.** Final publication needs stable appendix lettering after all cutpoints merge, final registry syntax, exact fixture-vector pass/fail profiles, and any closure on zero-item requests or deterministic encoding rules.

**Downstream dependencies.** Certification work should map each row to executable tests, fixture classes, and implementation evidence. T6 fixture/vector work should decide which current diagnostic and implementation-regression material becomes normative conformance-vector input.
